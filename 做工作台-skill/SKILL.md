# 做个人工作台

一套把「我有很多目标、资料和零散记录，想要一个自己的控制台」落成一个能真正每天用的软件的做法。
核心判断：**先做本地网页应用，不要一开始就做桌面 App。**

## 第 0 步：先问四个决定性问题

不要直接开工。这四个答案不同，后面代码结构完全不同。

1. **形态**：本地网页应用 / Electron-Tauri 桌面应用 / 部署到云端的网页？
   - 默认推荐**本地网页应用**：Node 起一个只监听 `127.0.0.1` 的服务，浏览器打开。
   - 理由：能读写本地文件、数据全在本机、迭代最快；后期套一层 Tauri 即可变双击启动的桌面 App，代码几乎不用改。
2. **LLM 怎么接**：用户自己有 API Key / 暂时手动 / 本地模型（Ollama）？
   - 有 Key 就做「目标 → 结构化任务列表」的规划器；没有就先做手动看板，把接口留出来。
3. **首版范围**：最小可用（首页 + 任务 + 一个垂直模块 + 文件预览）还是全模块？
   - **永远选最小可用**。工作台的价值来自每天用，功能多但跑不通等于零。
4. **要不要碰本地文件**：只是记录，还是要直接预览简历/PDF/项目文档？
   - 要预览就必须有本地服务端（纯前端不行，浏览器拿不到本地路径）。

## 第 1 步：把目标翻译成表

设计原则：**一个目标一个表，不要过早抽象成「万能实体」。**

判断「该建表还是塞 JSON 字段」：
- 需要筛选、排序、按它统计 → 建列或建表
- 只是附属说明（备注、问题清单、复盘） → 一个 TEXT 字段，前端按换行/序号渲染

典型个人的四张表（求职 + 学习型用户）：

| 表 | 用途 | 关键设计 |
|---|---|---|
| `tasks` | 所有待办 | `module` 打目标标签、`priority` P0-P2、`status` 三态、`due_date`、`source`（manual/llm/idea，用来回溯任务从哪来） |
| `ideas` | 随手捕捉 | `content` + `converted` 布尔，一键转任务后置为真，形成「捕捉→执行」闭环 |
| `interviews` / `records` | 垂直事件记录 | 一行一条事件，`questions` 和 `reflection` 用 TEXT，前端按换行渲染 |
| `logs` | 打卡 / 学习记录 | `module` + `category` + `score` + `duration(分钟)` + `date`，同一张表同时服务「雅思四项」和「技术学习」 |

**必须给 `done_at` 单独存日期**，否则「本周完成了几件事」算不出来。

## 第 2 步：本地服务（零依赖）

用 Node 22+ 内置的 `node:sqlite`，**不装任何 npm 包**：
没有 native 编译、没有依赖升级、没有下载失败，双击就能跑。

```
server.js      HTTP 服务 + 路由 + 静态资源 + LLM 代理 + 文件预览
db.js          DatabaseSync 连接 + 建表 + 时间工具
public/        index.html / style.css / app.js
data/workbench.db
config.json    模型配置 + 挂载的文件夹
启动.bat       node server.js --open
```

接口约定（够用就好，不要引入 REST 框架）：
- `GET /api/bootstrap` 一次返回全部数据 + 统计，前端一次请求搞定首屏
- 每个实体一组 `GET / POST / PATCH /:id / DELETE /:id`
- 写操作后前端重新 `bootstrap`：个人数据量小，这比维护局部状态便宜得多

## 第 3 步：文件预览（这是最容易翻车的地方）

必做的四件事：

1. **只读**：只提供 list / raw / text 三个只读接口，绝不提供删除或写入
2. **路径越界校验**：`path.relative(root, target)` 出现 `..` 或绝对路径 → 403。
   Windows 尤其要测 `C:\Windows` 这种跨盘符绝对路径和 `../../` 两种形态
3. **按扩展名分流**：
   - 图片 / 视频 / 音频 → `/api/raw` 直接流式返回，带正确 Content-Type
   - PDF → `<iframe src="/api/raw">`，浏览器自带阅读器就能翻页
   - md / txt / 代码 → `/api/text` 读成字符串，md 用极简渲染器转 HTML，代码丢 `<pre>`
   - docx / xlsx / pptx → **不要试图网页内渲染**，给「用本机程序打开」按钮（`spawn('explorer.exe', [path])`，避免 shell 引号问题）+ 下载链接
4. **大文件保护**：文本超过 ~4 MB 不内联渲染；`/api/raw` 支持 Range，视频和 PDF 才不会卡

## 第 4 步：前端

不要上框架。单页 + 一个视图函数一个页面，够用且改起来快。

```
TABS = [{id, label}]            → 左侧导航
viewXxx() 返回 HTML 字符串       → 每个页面一个函数
renderMain() 按 S.tab 分发
ACTIONS = { 'act-name'(el){...} } → 所有交互
document.addEventListener('click', e => e.target.closest('[data-act]'))
```

这套模式的好处：任何新功能 = 一个 view 函数 + 一个 action，不用记状态管理。

视觉上默认走**黑白灰**：`#111` 文字、`#fff` 卡片、`#e5e5e3` 描边、无阴影、圆角 10px，
用一个 `.pill` 组件表达所有状态（优先级用纯黑底白字突出 P0）。信息密度比装饰重要。

## 第 5 步：LLM 拆任务

用 OpenAI 兼容接口（一套代码同时支持 DeepSeek / 豆包方舟 / OpenAI / 通义）。

三条硬规则：
1. **让模型只输出 JSON**，system prompt 里明确「只输出合法 JSON」，再用「截取第一个 `{` 到最后一个 `}`」兜底解析（模型经常裹 ````json` 围栏）
2. **由代码接管校验**：due_date 格式、是否落在周期内、priority 是否合法、title 是否为空 —— 不信模型
3. **先生成草稿，用户勾选后再入库**。不要直接写库：模型拆出来的任务总是有 20% 是废话，让用户一键剔掉，信任感完全不同

prompt 里必须塞进用户背景（专业、年级、求职方向、当前水平、每天可投入时间），
否则拆出来的任务全是「学习 XX」这种不可执行的条目。

## 第 6 步：动效（加什么、不加什么）

动效不是装饰，它只承担三种信息，超出这三种就别加：

1. **因果**：我这一下操作，导致了什么？（纸飞机从按钮飞向灵感列表 = 这条灵感去哪了）
2. **位置**：东西从哪来、到哪去？（新条目从列表顶部滑入）
3. **进度**：还要多久？（`<span class="spin">` 转圈、"拆解中…"）

### 判据表

| 该加 | 不该加 |
|---|---|
| 操作后有「物品移动」语义的（保存、归档、拖到某列） | 纯好看的：粒子、发光、渐变扫过、波浪 |
| 列表/看板新增或消失条目 | 每次渲染都播的入场动画（切个页签就全屏动一遍会烦） |
| 按压、勾选这类高频小动作的即时反馈（≤150ms） | 数字滚动、打字机效果 |
| 状态切换（弹窗、抽屉、加载） | 超过 800ms 的「电影感」转场 |

### 时长与曲线

- 按压/勾选 100–150ms · 入场 220–420ms · 跨屏飞行 500–620ms
- 曲线：入场/落位用 `cubic-bezier(.22,.61,.36,1)`；回弹（勾选打勾）用 `cubic-bezier(.34,1.56,.64,1)`
- **一次操作只允许一个「注意力焦点」动效**（这里是飞机），其余全部压到 100ms 级微反馈，否则互相抢戏

### 实现约定（不装动画库）

- CSS `@keyframes` + 用 CSS 变量从 JS 传几何量：
  `plane.style.setProperty('--dx', (tx - sx) + 'px')`，keyframes 里用 `calc(var(--dx) * .55)`
  这样弧线可以在 keyframes 里写死，JS 只负责起终点，不用引 GSAP
- 起点用 `getBoundingClientRect()` 取真实坐标，`position: fixed` 叠在 body 上，动画结束后 `remove()`
- **必须**有 `@media (prefers-reduced-motion: reduce)` 降级：关掉飞行和入场，只留状态切换
- 动效不能阻塞业务：先发请求，再等动效结束刷 UI（`const flying = flyPlane(...); await api(...); await flying; await load();`），
  这样即使动画哪天被关掉，数据流程也不受影响

### 自查

加完动效问三个问题，任一答不上就删掉：
- 关掉这个动效，用户会误解什么吗？（答"不会" → 装饰，删）
- 连续点十次会不会烦？
- 弱网/慢机器上它会不会卡成幻灯片？（动效只用 `transform` / `opacity`，不碰 `left/top/width`）

### 牌堆 / 空间隐喻（灵感这类「多、碎、随手看」的数据）

什么时候该用牌堆而不是列表：条目彼此等价、主要用途是**随手翻看和偶遇**，而不是精确查找。
一旦用户需要「找到那条 / 按标签筛 / 批量删」，就必须还有列表视图 —— 两者并存，牌堆放首页，全量列表放二级页。

四个实现要点：

1. **布局参数化，动画交给容器**。容器的 CSS 变量 `--gap`（横向错位）、`--fan`（是否扇形展开）、`--rot`（张角）定义在 `.deck-stage` 上，每张卡用内联 `--i`（居中后的索引，如 -2…2）乘它们：
   `transform: translateX(calc(var(--i) * var(--gap))) translateY(calc(var(--ay) * var(--fan))) rotate(calc(var(--i) * var(--rot)))`
   展开只需要 `:hover` 改容器上的这三个变量，五张卡一起动，不用 JS 重排、不用逐张写动画。弧形下落量 `--ay` 在渲染时用 `k*k*3.4px` 算好塞进内联样式（CSS 没有 `abs()` 就别指望它）。
2. **抽出来**要给三样东西：`translateY(-22px)`（离开叠）、阴影（脱离纸面）、`z-index`。注意 z-index 是内联写死的，`:hover` 想盖过它必须 `!important`。
3. **随机抽牌**：从**全量**里抽，但只展示 5 张 —— 抽到的卡如果不在展示集合里，渲染时必须把它塞进叠里当「最上面那张」，否则会出现"抽到了但看不见"的 bug。
4. 洗牌动效加在**整叠**（容器 keyframes：晃一下 + 轻微旋转），抽牌结果 500ms 后再上屏，读起来才是「洗一下 → 翻开一张」。

## 第 7 步：完成态要带证据（复盘闭环）

工作台最大的失败模式不是「功能少」，而是**数据失真**：勾一下就完事，三个月后满屏"已完成"，但你既想不起做过什么，也分不清哪些是真做完的。

解法是把「完成」从一个布尔值改成一个**事件**：

1. 勾选框不直接写 `status = done`，而是弹一个必填的两段式记录：
   - **做到哪一步 / 交付物**（必填，禁止只写"完成"）—— 逼出具体事实
   - **学到了什么**（必填，一句话即可）—— 逼出迁移性认知
2. 服务端只开一个 `POST /api/tasks/:id/complete` 接口：校验两段非空 → 置 `status=done` + `done_at` → **同一次请求里**插入一条 review 记录。不提供"只改 status 就算完成"的路径，前端也不许绕过。
3. 新表 `reviews(task_id, task_title, module, content, learned, minutes, date)`，**冗余存一份 task_title**：任务以后被改名或删除，日记里的历史不该跟着变。
4. 撤销（done → todo）**不删复盘**：那条记录是"那天确实做到了"，是历史，不是状态。
5. 落一个「复盘日记」页按日期分组展示，首页只放最近 3 条做钩子。

一句话原则：**状态机的终态必须有配套的不可变记录，否则终态只是个开关。**

## 验收清单

跑完必须逐条验过，缺一条都不算完成：

- [ ] 增删改查四个操作都能从界面走通，不是只有接口能通
- [ ] 空状态有引导文案（新用户第一次打开不该看到一片空白）
- [ ] 中文正常（写入、读取、统计、排序都不乱码）
- [ ] 完成任务的勾选会实时改变统计数字
- [ ] 文件预览：图片 / PDF / md / 不支持格式 四种都试过
- [ ] 路径越界被拒（`../../` 和 `C:\Windows`）
- [ ] 没配 Key 时点「生成计划」给出可读的错误提示，不是白屏
- [ ] 重启服务数据还在
- [ ] 浏览器刷新后状态正确
- [ ] 动效：开系统「减少动态效果」后界面仍可用（`prefers-reduced-motion` 生效）
- [ ] 勾完成必须先写复盘，少写任一段接口返回可读的 400，不是静默放过
- [ ] 撤销完成不删复盘，日记里历史还在

## 常见坑（都已踩过）

| 现象 | 原因 | 解法 |
|---|---|---|
| SQLite 报 `no such column: ""` | SQLite 里双引号是标识符不是字符串 | SQL 一律用单引号 `''`，在 JS 单引号字符串里写成 `\'` |
| 接口 500，`today` 字段为空 | 返回的是函数引用，JSON.stringify 会丢掉 | 写成 `today()` |
| 用 PowerShell 测接口，中文全变 `?` | `Invoke-RestMethod -Body` 默认按非 UTF-8 编码发送 | 用 Node 写测试脚本，或显式传 UTF-8 字节 |
| PDF 在 iframe 里灰屏 | 没等渲染 / 缺 Range 支持 | 加 `Accept-Ranges` + Range 分支，并留意加载需要几秒 |
| 用了 `explorer.exe` 打不开文件 | 参数被 shell 吞掉 | 用 `spawn` 传数组参数，不要拼字符串走 shell |
| 抽牌抽到「看不见的卡」 | 只渲染前 5 张，抽的是全量 | 渲染时把抽中的那张塞进叠里当 hero |
| 勾一下就能完成，库里全是「假完成」 | 完成被当成布尔开关 | 走 `complete` 接口，两段记录必填 + 同事务落 review 行 |

## 视觉自检（用机器能判定的标准，别靠感觉）

装好 [impeccable](https://github.com/pbakaus/impeccable) 后，对着跑起来的页面跑一次确定性扫描：

```bash
impeccable.cmd detect http://127.0.0.1:7788     # Windows
npx impeccable detect http://localhost:5173     # 有 Node 的环境
```

它不调用 LLM，只按规则查表，所以结果稳定、可以进验收清单。踩过的三条（本项目实测）：

| 规则 | 判定 | 修法 |
|---|---|---|
| `low-contrast` | 正文对比度 < 4.5:1。浅灰 `#a6a6a6` 在白底只有 2.4:1 | 弱化色压到 `#6b6b6b` 以上（`#616161` 最稳），层级靠字重和字号拉，不靠把字调白 |
| `tiny-text` / `undersized-ui-text` | 正文 < 12px，功能性小字（标签、日期、优先级）< 11px | 功能小字统一 11.5px 起，正文 12.5px 起；✓ 这类装饰性字形不受限 |
| `nested-cards` | 卡片里再套描边卡片 | 内层条目改成「无边框 + `border-top` 分隔线」，`:first-child` 去掉顶线 |
| `text-occlusion` | 文字被上层不透明元素 100% 盖住 | 一叠卡要叠放时属于设计意图（hover 扇开），在源码加豁免注释并写明理由；其它场景就是真 bug，把文字挪出叠压区 |

另一条不在规则表里、但机器能查的经验：**弹跳缓动 `cubic-bezier(.34,1.56,.64,1)` 已经过时**，换成指数缓出 `cubic-bezier(.22,1,.36,1)`，东西看起来是"落定"而不是"弹一下"。

## 迭代路线（不要一次做完）

- **v1**：任务看板 + 灵感捕捉 + 一个垂直模块 + 文件预览 + 设置
- **v2**：LLM 规划器、统计视图、周复盘
- **v3**：按目标拆成「项目 / 作品集」维度，把任务挂到项目下
- **v4**：套 Tauri 变桌面应用；再考虑多设备同步（那时才需要鉴权和云端）

每加一个模块，同步更新本文档的验收清单和坑位表 —— 这份文档本身就是要交付的「skill」。
